# FBT: трекінг усього тіла у VRChat з двох телефонів

[English](README.md) · **Українська**

Трекери ніг, таза, колін і грудей для VRChat на **Quest 3 (standalone)** без справжніх трекерів. Потрібні лише два старі Android-телефони і MacBook.

- Телефони знімають тебе з двох боків і шлють відео на Mac.
- Mac знаходить точки тіла на кожному кадрі нейромережею, рахує з двох видів 3D-скелет і шле трекери у VRChat по OSC.
- Камера самого MacBook допомагає як третій вид.
- Якщо VRChat надсилає позу шолома, трекери прив'язуються до справжнього шолома, а не до голови з камер.

Повна історія рішень, вимірювань і відкинутих варіантів — в [ARCHITECTURE.md](ARCHITECTURE.md). Цей файл — як запустити і як переробити під себе.

## Що потрібно

| | Що використано тут | Чим можна замінити |
|---|---|---|
| Комп'ютер | MacBook Air M3, 8 ГБ | Будь-який Mac на Apple Silicon. Інші ОС — див. [«Не Mac»](#не-mac) |
| Камери | Redmi 12 і Galaxy A32 (ширококутні задні камери) | Будь-які два Android 9+ телефони з Camera2 і апаратним H.264 |
| Третя камера (необов'язково) | вбудована камера MacBook | будь-яка камера, яку бачить macOS |
| Шолом | Quest 3, VRChat standalone | PC VR теж має працювати (OSC той самий), але не перевірявся |
| Мережа | усі пристрої в одній Wi-Fi | бажано 5 ГГц; телефони можна й кабелем (`adb forward`) |

Програмне: Python 3.11+ (тут 3.12), Xcode Command Line Tools (`swiftc`), Android SDK + JDK 17 (лише щоб зібрати застосунок для телефонів).

## Як це працює

```
 Телефон A ─┐  H.264 + час знімання кожного кадру (TCP :5000)
 Телефон B ─┼──────────────► Mac ──────────────────────────────► Quest / VRChat
 Камера Mac ┘                 │  1. 2D-поза: YOLOX-tiny + RTMPose-m        OSC :9000
                              │     (ONNX Runtime на GPU через CoreML)     /tracking/trackers/...
                              │  2. синхронізація кадрів за часом знімання
                              │  3. тріангуляція (DLT) з перевірками
                              │  4. стабілізатор: відсів викидів, довжини
                              │     кісток, фільтр One-Euro
                              │  5. трекери (позиція + поворот)
                              ◄─────────────── поза шолома (OSCQuery, UDP :9101)
```

**Застосунок для телефонів (FBT Cam, `android/fbtcam`).**
- Camera2 → апаратний H.264 → TCP-сервер на порту 5000.
- Кожен кадр несе час знімання з сенсора. Mac раз на секунду звіряє годинник із телефоном (пінг-понг), тому знає справжній момент кожного кадру. Так кадри двох телефонів зводяться без апаратної синхронізації.
- Раз на 5 с телефон шле заряд і температуру.
- Протокол описано в [PROTOCOL.md](android/fbtcam/PROTOCOL.md).

**Mac (`fbt/`, `fbtapp/`, `macapp/`).**
- `macapp/` — нативне вікно FBT.app (WKWebView). Запускає Python-сервер `fbtapp` і показує його інтерфейс. Окреме вікно потрібне, щоб macOS дала дозвіл на камеру і локальну мережу саме FBT.
- `fbtapp/server.py` — локальний сервер на `127.0.0.1:8765`: сторінка, відео камер зі скелетом, стан, налаштування.
- `fbt/engine.py` — серце: камери з автоперепідключенням, калібрування, цикл трекінгу, вивід у VRChat, логи.

**Калібрування** (30 с, кнопка «Калібрувати»).
- Положення телефонів знаходиться по твоєму тілу, без шахівниці: ті самі точки тіла з двох видів → essential matrix → bundle adjustment.
- Масштаб береться з твого зросту.
- Камера Mac калібрується окремо (PnP), разом із її фокусною відстанню і зсувом годинника.
- Заодно міряються довжини твоїх кісток, вони потім тримають скелет стабільним.

**Прив'язка до шолома.**
- VRChat може слати позу шолома по мережі (OSCQuery).
- FBT вчиться перетворенню між своїм простором і простором VRChat і шле трекери вже у просторі VRChat. Голова — це справжній шолом.
- Т-поза миттєво задає поворот. Далі прив'язка повільно уточнюється у фоні.
- Без даних шолома все працює за головою з камер.

## Встановлення

### 1. Python-частина

```bash
git clone <цей репозиторій> fbt && cd fbt
python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest -q
```

- Моделі (RTMPose-m Halpe26 і YOLOX-tiny) `rtmlib` сам завантажує при першому запуску в `~/.cache/rtmlib`.
- FBT робить з них версії з фіксованим розміром у `models/`, бо інакше CoreML мовчки рахує на CPU в 2–5 разів повільніше.
- Перший запуск триває ~хвилину, потім усе з кешу.

### 2. Застосунок FBT для Mac

```bash
macapp/build.sh
```

- Збирає `FBT.app` і ставить у `~/Applications`, звідки він доступний через Spotlight, Launchpad і Dock.
- Шлях до репозиторію вшивається в застосунок, тож папку потім не переносити, або перезібрати.
- При першому запуску macOS спитає дозвіл на камеру і локальну мережу. Дозволь обидва.
- Без застосунку: `.venv/bin/python -m fbtapp --browser` відкриє той самий інтерфейс у браузері. Тоді дозвіл на камеру Mac треба дати Terminal.

### 3. FBT Cam на телефони

Увімкни на телефонах «Для розробників» → «Налагодження по USB», підключи кабелем:

```bash
cd android/fbtcam
./gradlew assembleDebug
~/Library/Android/sdk/platform-tools/adb install -r app/build/outputs/apk/plain/debug/app-plain-debug.apk
```

Є три варіанти збірки (flavor):

| Варіант | Ім'я пакета | Для чого |
|---|---|---|
| `plain` | `dev.fbt.cam` | будь-який телефон, почни з нього |
| `samsung` | `com.samsung.android.scan3d` | Samsung |
| `xiaomi` | `com.xiaomi.cameratest` | Xiaomi / Redmi |

Навіщо `samsung` і `xiaomi`:
- Деякі виробники показують ширококутну камеру лише застосункам зі «своїми» іменами пакетів. Під іншим іменем застосунок бачить тільки основну камеру.
- Ширококутна камера бачить усе тіло з меншої відстані, тому вона краща.
- Ці збірки лише для власних телефонів. Не публікуй їх у магазинах: ім'я пакета там чуже.

Встанови потрібний APK (`app/build/outputs/apk/<варіант>/debug/`), відкрий FBT Cam і вибери:
- **камеру:** найширшу, з поміткою «ширококутна»;
- **режим:** 640×480, 30 к/с. Більша роздільність якості не додає, а телефон гріється сильніше (вимірювання в [ARCHITECTURE.md §25](ARCHITECTURE.md)).

Застосунок одразу починає роздавати відео. Екран телефона можна вимкнути, лише не закривай застосунок.

### 4. Мережа

- Mac, обидва телефони і Quest — в одній мережі.
- Закріпи за телефонами і Quest постійні IP у роутері (DHCP reservation), інакше після перезавантаження доведеться міняти їх у налаштуваннях.
- IP телефона показує FBT Cam. IP Quest: Налаштування → Wi-Fi → твоя мережа.

### 5. VRChat

У VRChat (Action Menu → Options → OSC):
- **Enabled** — увімкни.
- **Allow Sending Head and Wrist VR Tracking OSC Data** — увімкни, щоб працювала прив'язка до шолома.

Нюанси:
- VRChat шле позу шолома лише сервісу, який знайшов **після** того, як цей пункт увімкнено. Тому спершу пункт, потім FBT.
- Якщо FBT пише «дані з шолома не йдуть», перезапусти VRChat.
- Без цього пункту трекери все одно працюють, просто прив'язані до голови з камер.

## Розстановка камер

```
            стіл
   [Телефон A]   [MacBook]   [Телефон B]
        \            |            /
         \           |           /
          \      ігрова зона    /
           \        (ти)       /
```

- **Телефони:** зліва і справа спереду, між ними ~2 м, кут між напрямками 60–90°. Висота ~1.1 м, вертикально.
- **Кадр:** кожен телефон має бачити тебе повністю, від голови до ступнів, у всій зоні, де граєш.
- **MacBook:** посередині, кришка під кутом, щоб камера бачила тебе. Особливо допомагає сидячи: втрачених точок ніг у 9 разів менше.
- **Світло:** чим світліше, тим менше змазування ніг у русі.
- **Після калібрування камери не рухай.** Якщо зрушив, відкалібруй заново.

## Користування

1. Відкрий FBT Cam на обох телефонах і FBT на Mac. Угорі видно, які камери на зв'язку і скільки заряду.
2. **Перший раз:** ⚙︎ → вкажи зріст, IP телефонів і IP Quest.
3. **«Калібрувати»** (один раз, і щоразу, як зрушиш камери). 30 секунд спокійно ходи по всій зоні:
   - ближче і далі, ліворуч і праворуч;
   - присідай, піднімай руки вгору і в сторони;
   - постій кілька секунд рівно.

   Тебе весь час має бути видно повністю обома телефонами. Не завмирай, але й не метушись.
4. **«Почати гру»** — великий екран стану, видно з відстані.
5. **У VRChat** стань у Т-позу і натисни Calibrate FBT. FBT у цю ж мить вирівнює трекери за Т-позою.
6. Грай. Якщо трекери поїхали, ще раз Т-поза + Calibrate FBT.

### Налаштування (⚙︎)

Усе застосовується одразу, навіть під час гри. Зберігається в `data/app_settings.json`.

| Налаштування | Що робить |
|---|---|
| Груди / Коліна / Лікті | додаткові трекери. Таз і стопи завжди увімкнені |
| Стопи завжди рівно | стабільніше, але без носочків |
| Плавність тіла | нижче — плавніше, але з запізненням |
| Передбачення руху тіла | ховає затримку, але може «перелітати». Типово 0 |
| Трекери вперед / назад | якщо кубики в грі зсунуті від тіла |
| Передбачення / плавність голови | для режиму без шолома: щоб ноги не відставали при нахилах |
| Поправка повороту | якщо тіло в грі трохи розвернуте |
| Частота камери MacBook | 10 к/с вистачає; більше — Mac гріється без помітної користі |
| Прив'язувати до шолома | використовувати позу шолома, коли VRChat її шле |
| Камера MacBook | третій вид увімкнено чи ні |
| Голосові попередження | у грі скаже, якщо телефон відключився або сідає |

## Як переробити під себе

### Інші телефони

- Збери `plain` і подивись, які камери показує FBT Cam.
- Якщо ширококутної немає у списку, твій виробник її ховає. Тоді або основна камера (став телефони далі), або окремий flavor з іменем пакета, який виробник пускає до цієї камери (див. `android/fbtcam/app/build.gradle.kts`). Як шукати такі імена — `android/camprobe` перебирає всі приховані id камер.
- Фокусна відстань і розмір сенсора приходять від телефона, калібрування їх уточнює.
- Перевірити затримку і частоту: `.venv/bin/python -m tools.fbtcam_check <ip1> <ip2>`. Тут Redmi дає ~72 мс від знімання до Mac, Samsung ~111 мс.

### Інша камера замість телефона

- Mac приймає джерела, задані рядком у `cameras` (`data/app_settings.json`):
  - IP телефона з FBT Cam;
  - `mac` або `mac:<номер пристрою>` — камера, яку бачить macOS (`mac@1920x1080` — з розміром);
  - `replay:<папка запису>/camN` — запис замість живої камери, для тестів.
- Новий тип камери: напиши клас-джерело за зразком `fbt/maccam.py` або `fbt/fbtcam.py`. Головне — **справжній час знімання** кожного кадру на годиннику `time.perf_counter`, без нього синхронізація розвалюється.
- Розбір рядка — у `open_source()` (`fbt/maccam.py`).

### Скільки камер

- Інтерфейс розрахований на 2 телефони + необов'язкова камера Mac.
- Телефони задають моменти кадрів, третя камера лише допомагає (її поза інтерполюється на той самий момент).
- Більше камер ядро тріангуляції підтримує (`fbt/triangulate.py`), але калібрування і інтерфейс доведеться розширити.

### Інша модель пози

- `fbt/pose.py`, `make_backend("rtmpose-m:gpu")`. Пристрої: `cpu`, `gpu`, `ane`, `all`.
- Є також `rtmpose-x` (точніша, повільніша) і `mediapipe-full` (на наших записах слабша).
- Важкі моделі на M3 давали менше кадрів і не кращий результат (порівняння в [ARCHITECTURE.md §21](ARCHITECTURE.md)).
- Точки тіла — формат Halpe26 (є п'яти і пальці ніг, це важливо для повороту стоп).

### Інший зріст / аватар

- Зріст — у налаштуваннях, він задає масштаб.
- Якщо ноги аватара ближчі чи ширші, ніж твої (наприклад, chibi), це пропорції аватара: роби Calibrate FBT у VRChat, ставши так, як стоїть аватар.

### Не Mac

- Ядро (`fbt/`) — звичайний Python: OpenCV, ONNX Runtime, SciPy. На Linux/Windows має працювати з `rtmpose-m:cpu` і `python -m fbtapp --browser`. Не перевірялось.
- Специфічне для macOS:
  - `macapp/` (вікно застосунку);
  - `fbt/maccam.py` (камера через AVFoundation);
  - заряд і нагрів Mac (`pmset`), `caffeinate`, голос (`say`);
  - прискорення через CoreML.
- На CPU поза рахується повільніше (~17 мс замість ~5 мс на M3), тож потрібен швидкий процесор.

### Інша гра / шолом

- Вивід — стандартний OSC-трекінг VRChat (`fbt/osc_out.py`, порт 9000): `/tracking/trackers/N/position|rotation` і голова для вирівнювання.
- Для PC VR став `quest_ip` = `127.0.0.1` (або IP ПК). Поза шолома через OSCQuery там теж має приходити, але це не перевірялось.

## Структура

```
fbt/            ядро
  engine.py       камери, калібрування, трекінг, вивід, логи (використовує FBT.app)
  fbtcam.py       прийом відео з FBT Cam, синхронізація годинника
  maccam.py       камера Mac (AVFoundation через PyAV) і розбір рядків джерел
  sources.py      базове джерело кадрів, відтворення записів
  pose.py         моделі 2D-пози, фікс для CoreML
  calibrate.py    калібрування за тілом (пара телефонів + третя камера)
  triangulate.py  тріангуляція з перевірками (плутанина лівого/правого, довжини кісток)
  filters.py      стабілізатор скелета, One-Euro, вивчення довжин кісток
  trackers.py     позиції і повороти трекерів, Т-поза
  hmd_align.py    прив'язка до шолома
  oscquery.py     сервіс OSCQuery (поза шолома від VRChat)
  osc_out.py      OSC у VRChat
fbtapp/         локальний сервер і інтерфейс (ui/)
macapp/         нативне вікно FBT.app, build.sh
android/fbtcam  застосунок FBT Cam для телефонів, PROTOCOL.md
android/camprobe  діагностика: які камери телефон показує і кому
tools/          запис, офлайн-калібрування, вимірювання, перевірки
tests/          pytest, без камер і без шолома
data/           (не в git) калібрування, налаштування, записи, логи
models/         (не в git) моделі і кеш CoreML
```

### Корисні інструменти

```bash
.venv/bin/python -m tools.fbtcam_check 192.168.1.20 192.168.1.21                   # частота і затримка телефонів
.venv/bin/python -m tools.record 192.168.1.20 192.168.1.21 mac --seconds 30        # синхронний запис (з Terminal.app, якщо є mac)
.venv/bin/python -m tools.calibrate --rec data/rec_X --height 1.75 --out calib.json # офлайн-калібрування запису
.venv/bin/python -m tools.eval_recording --rec data/rec_X --calib calib.json        # якість 3D на записі
.venv/bin/python -m tools.hmd_probe                                                # чи шле VRChat позу шолома
.venv/bin/python -m tools.fake_vrchat                                              # «VRChat» на Mac: що саме ми шлемо
.venv/bin/python -m fbtapp --port 8766 --data <копія data/> \
    --cameras replay:data/rec_X/cam0,replay:data/rec_X/cam1,replay:data/rec_X/cam2  # FBT на записі замість камер
```

Кожен інструмент має опис на початку файла (`tools/*.py`).

## Якщо щось не так

| Симптом | Що робити |
|---|---|
| Телефон «не в мережі» | FBT Cam відкритий? IP той самий? Телефон і Mac в одній мережі? |
| Каша замість відео після зміни режиму в FBT Cam | стара версія FBT Cam: онови її. Або перезапусти FBT |
| «Змінилась роздільність — відкалібруй ще раз» | режим у FBT Cam не той, що був при калібровці: поверни його або відкалібруй |
| «Дані з шолома не йдуть» | у VRChat увімкнено пункт про Head and Wrist Tracking? Перезапусти VRChat (він тримається за перший знайдений сервіс) |
| «Схоже, камери зрушили» | відкалібруй заново |
| Ноги лагають | Mac на низькому заряді сильно сповільнюється: постав на зарядку |
| Кубики трекерів зсунуті вперед/назад | слайдер «Трекери вперед / назад» |
| Трекери розвернуті | Т-поза + Calibrate FBT у VRChat |
| Камера Mac не працює | Системні параметри → Конфіденційність → Камера: дозволь FBT. Після перезбирання FBT.app macOS може спитати ще раз |

Логи гри — у `data/logs/` (5 останніх сесій). Записи калібрувань — у `data/rec_*`.
